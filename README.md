# Ringostat RevOps dashboard (тестове завдання)

Streamlit-дашборд по таблиці угод: win rate по країнах і CRM, розподіл по стадіях, угоди по джерелах, залежність win rate від PPC budget, тренд по місяцях AQL, вкладка Data issues (12 перевірок).

## Запуск
```bash
pip install -r requirements.txt
streamlit run app.py
```

## Файли
- `app.py` — інтерфейс і графіки
- `revops_lib.py` — завантаження даних, розрахунок win rate, правила data quality
- `data/deals.xlsx` — вихідна таблиця (копія шаблону)
- `INSIGHTS.md` — RevOps Insights Summary
- `AI_USAGE.md` — використання AI

## Рішення в розрахунках
- **Win rate = Won / (Won + Lost).** Відкриті угоди (28%) виключені, бо їх результат невідомий.
- Країни та CRM з малою кількістю закритих угод (за замовчуванням менше 15) групуються або приховуються, а їхні стовпці на графіку сірі. Повзунок у боковій панелі змінює поріг.
- «Is not using» об'єднано з «No CRM» у графіках, а в Data issues це позначено як окрема перевірка.
- PPC budget — діапазони, тому графік категоріальний, не точковий. Колонку інтерпретуємо як рекламний бюджет клієнта (припущення, у даних не описано).
- Дата вивантаження таблиці невідома, тому аналіз зроблено станом на дату останньої угоди (3 квітня 2024). Відкриті угоди вважаємо відкритими на цю дату, а не «завислими» чи помилкою менеджерів.
- Тренд по місяцях: останні місяці ще не дозріли (багато відкритих угод), тому їх win rate не можна порівнювати з січнем напряму. Неповний місяць позначено зірочкою.
- Серйозність проблем у Data issues: High — запис суперечить власній стадії, Medium — порушене правило поля або можливий дубль, Low — підозріле, але можливе значення. Дублікати не можна підтвердити без ID угоди, тому це Medium, а не High.
- Data issues рахуються по всьому набору даних, фільтри на них не впливають. Номери рядків збігаються з вихідною таблицею.
